# 闸门对照回测工具（校验记录）

脚本：`quant-python/signal_system/market_gate_comparison_study.py`

> 原名 `tmp_gate_window_compare.py`。任务完成后**提升为常驻研究工具** ——
> 它是回答"闸门在某窗口是否有效"的通用入口，且已通过校验。
> 配套：`research_sample_builder.py`（建样本，任意窗口）、
> `market_gate_cost_impact.py`（成本敏感性对照）、
> `backfill_history_cache.py`（回填日线缓存到指定起点）。

## 它做什么

在指定窗口内跑「有闸门 / 无闸门 × 三策略」六格对照：

- **无闸门**：样本自带信号原样入场（与既有冻结研究同口径）。
- **有闸门**：先用 `build_market_gate` 求逐日 `allows_entries`，**剔除入场日落在
  关闭日的信号**，其余不变。
- 离场方案取各策略既有最优：零轴金叉 `ladder_b`、年线趋势 `none`、底背离 `ladder_b`。
- 止损沿用归档值：10% / 3% / 6%（`ARCHIVED_STOP`）。

## 关键实现点

`.signals.json` 里的索引是**全历史绝对 bar 位置**，不是窗口内偏移。
因此过滤"入场日是否开放"时，必须用 history frame 自己的日期解析：

```python
dates = pd.to_datetime(frame["datetime"]).dt.strftime("%Y-%m-%d").tolist()
keep = {i for i in indices if allowed.get(dates[i], False)}
```

若误用样本的 `dates`（只覆盖窗口内）会索引错位或越界。

`build_cache_sample` 写出的 `prepared_metadata.json` **不含 `config_snapshot`**
（那只在 `run()` 汇总时补上），故脚本从 H1 冻结归档
`divergence-stop-1to10-250k-2024h1-bd36d220/comparison.json` 取同一份快照。

## 校验：2024H2 六格全部复现

对 `scale-out-take-profit-250k-2024h2-oos` 的样本（4645 只，125 交易日，
闸门开放 39/125 = 31.2%）跑本工具，与既有归档逐一比对：

| 策略 | 闸门 | 本工具 | 归档 | |
|---|---|---:|---:|:--:|
| 日线零轴金叉 | 无 | +1.00% (33笔) | +1.00% | ✅ |
| 日线零轴金叉 | 有 | −17.20% (10笔) | −17.20% | ✅ |
| 年线趋势 | 无 | +14.79% (44笔) | +14.79% | ✅ |
| 年线趋势 | 有 | +3.21% (16笔) | +3.21% | ✅ |
| 零轴＋底背离 | 无 | +11.15% (26笔) | +11.15% | ✅ |
| 零轴＋底背离 | 有 | −0.83% (9笔) | −0.83% | ✅ |

**6/6 精确一致。** 其中"有闸门"三格是脚本自己用 `restrict()` 过滤算出来的，
不是从归档抄的 —— 说明闸门判定与过滤逻辑正确。
