# 首板低开前向纸面账本（100 万）

- 启动：2026-11-22；账本起点 2026-10-30 收盘（回测样本的最后一天），空仓
- 初始资金：1,000,000 CNY
- 状态目录：`quant-python/signal_system/state/forward_low_open_1m/`（gitignore，不入库）
- 规则：2026-11-15 归档的「首板低开 · 单票≤1/3」，选股和账户直接调用回测代码（`first_board_four_strategies_study` 的 `build_signals` / `StrategyPortfolio`），没有另写一份
- 约束：**只做纸面账本，不接券商，不下单，不改参数**

## 规则（冻结）

- 信号：昨日首板（非连板）、今日低开 3%–4%、60 日相对位置 ≤ 50%、上市满 250 日
- 买入：空仓时开盘买入当日全部候选，单票 = min(总资产 ÷ 候选数, 总资产 × 1/3)；持仓期间出现的新信号只记录、不买
- 卖出：次日起收盘卖出；收盘涨停继续持有，收盘跌停卖不掉
- 成本：佣金 3bp/边（最低 5 元）、卖出印花税 10bp、滑点 10bp/边；100 股整手

## 运行方式

```bash
# 每个交易日 21:30 由 cron 运行（生产行情缓存 18:00 开始刷新，约 20:20 刷完）
scripts/run_forward_low_open.sh

# 只查看，不改变状态
cd quant-python/signal_system
../.venv/bin/python forward_low_open.py --action status
```

- 行情来源：`/opt/docker/quant/cache/daily_history/*_qfq.pkl`（生产每日刷新的前复权日线）。
- 幂等：账本只从 `last_session` 之后推进，重复运行不会重复成交。
- 行情没刷到最新交易日，或最新一天的股票数不到前一天的 98%，直接报错、不动账本；漏掉的交易日下次自动补上并标记 `backfilled`。
- 日志：`quant-python/signal_system/logs/forward_low_open.log`。
- 失败报警：运行退出码非 0 时，把错误推送到 Web 设置页里已启用的通知渠道（当前只有 Bark）。
- 心跳：交易日 22:30，systemd 用户定时器 `quant-ledger-heartbeat.timer` 运行 `ledger_heartbeat.py`，账本没推进到最新交易日就推送到同一组渠道。它不走 cron，所以 cron 没在跑时也会报。整台机器关机或断网时仍然没有报警。单元文件和安装方法：`scripts/systemd/`。
- 开盘成交的历史复测：`../2026-11-22-first-board-low-open-fill/memo.md`。量够，但开盘头 5 分钟均价平均比开盘价高 0.81%，按均价买入的单笔均值从 +1.46% 降到 +0.63%。账本规则不因此改动；复盘时"开盘价能否成交"一项要看 9:30 之后实际能买到的价格，不只是数一字板。

## 每日看板（2026-11-25 加入）

<https://quant.illsky.com/research/forward-low-open/>，每个交易日 21:30 随账本一起更新。给人在次日开盘前看，不改账本规则。

- **观察名单**：收盘后就能确定的下一个交易日候选，也就是除"低开 3%–4%"以外的条件都已满足的股票，附能触发信号的开盘价区间（昨收 × 0.96 ~ 0.97，含两端，0.01 元一档）。"低开"要到次日 9:25 竞价结束才知道，前一晚只能给到这一步。
- 名单的算法：在行情末尾补一根假想的 K 线（每只都开在区间正中），再走一遍回测的 `build_signals`，和账本用的是同一份选股代码。最近 45 个交易日（2026-09-14 → 2026-11-23）逐日核对过：名单合计 618 只次，次日实际出的 18 个信号全部在名单里，"开盘价是否落在区间内"与"是否出信号"没有一处不一致。
- 页面其余部分：当前持仓和下一个交易日怎么做、当天账本记的信号和卖出、账本概况、最近 30 笔成交。
- 持仓表的"现价"是账本所在交易日的收盘价（停牌沿用最后成交价），和权益同口径，存在持仓的 `mark_price` 里。持仓的 `last_price` 是回测内部状态，买入次日的卖出环节才更新，买入当天等于买入价，不能当现价用（2026-11-25 当晚的第一版页面用错了，买入当天显示 +0.00%，同晚已改）。
- 名单存在账本的 `watchlist` 里，只保留最新一份。
- 页面上的"用于 X 开盘"按下一个工作日算（行情源的交易日历没有未来的日期），节假日前会偏早，页面注明"遇休市顺延"；打开页面的日期晚于 X 时会显示过期提示。"上市满 250 天"也按 X 判断，长假前正好卡在 250 天上的股票会被名单漏掉（账本不受影响）。
- 名称和 ST 标记来自 BaoStock。页面先写一版只有代码的，名称取到后再覆盖，所以 BaoStock 卡住或登录失败时名单照常更新，只是没有名称。
- 当晚的推进失败（行情没刷完等）时页面不更新，照常走失败报警；第二天打开会看到过期提示。
- 名单的规模（研究面板 2025-01-02 → 2026-10-30，441 个交易日）：中位数 5 只、均值 9.3 只、九成交易日不超过 22 只；64 个交易日（15%）有信号，名单内单只的触发率 2.3%。

## 9:25 判信号并推送（2026-11-26 加入）

每个交易日 9:25 由 cron 运行 `scripts/run_forward_low_open_auction.sh`，不改账本。

- 取观察名单里每只股票的竞价开盘价（新浪实时行情，取不到的用腾讯补），开盘 ÷ 昨收落在 0.96 ~ 0.97 的就是当天的信号，连同账本会买的股数推送到 Web 设置页里已启用的通知渠道。每个交易日一条，没有信号也推（附最接近区间的 3 只）；休市日不推。
- 只认行情时间在 9:25:00 之后、开盘价大于 0 的行情：之前是虚拟撮合价。第一只出开盘价后最多再等 10 秒，仍没有开盘价的（停牌、竞价没成交）在推送里单列，要自己看。
- 昨收用行情里的。遇除权除息它是除权参考价，和账本晚上用的前复权昨收一致，推送里会注明。多数股票的昨收和名单对不上时，说明名单不是给今天用的（前一晚账本没推进），报错不判。
- 股数直接调用账本的买入代码。用账本已有的 5 个买入日（9 笔）回放过，股数全部一致。账本有持仓时信号照推，但不带股数。
- **9:30 后的价格**：推送之后继续盯信号股到 9:35，每 3 秒记一次盘口，算出 9:30 前最后一次看到的卖一、连续竞价第一笔成交的均价、到 9:31 和 9:35 的成交均价（都不含竞价那一笔）。这是"收到推送再下单能买到什么价"的直接记录，日线和 5 分钟线都给不了。
- 记录按天写在 `state/forward_low_open_1m/auction/<日期>.json`，一天只判一次。
- 对账：晚上账本推进之后，`run_forward_low_open.sh` 接着运行 `forward_low_open_auction.py --action reconcile`。当天没有早盘记录，或推送的信号、股数和账本记的不一致，就报警。对账输出里的 `fills` 是全部早盘记录的汇总（各个价格平均比开盘价高多少）。
- 失败报警：取不到行情、名单过期、推送没发出去、对账不一致，都走 `ledger_cron.sh` 的报警。日志：`quant-python/signal_system/logs/forward_low_open_auction.log`。
- 没验证过的：9:25 那一刻行情源的表现（开盘价几秒后出现、时间戳怎么写）。上线当天 9:25 已过，只在 9:53 补判了一次（3 个信号，推送成功），9:30 后的采样只在盘中用实时行情试过。第一次真正的 9:25 运行是 2026-11-27。
- 9:30 后的价格是描述性记录，不是新增的判定项；样本和成交一样少，满 30 个信号之前不下结论。

## 账本里额外记录的三项诊断

回测有几处已知近似，前向账本顺带收集数据来检验它们。三项都从 BaoStock 取数，失败不影响账本，下次运行自动补。

1. **源码卖点**：聚宽源码在 11:28 有浮盈就卖、14:50 清仓，回测用收盘价近似。账本对每笔成交用不复权 15 分钟线的 11:30 / 14:45 两根收盘价重放一遍，记在 `source_exit` / `source_net_return`。账本净值仍按收盘卖出计，这一项只是对照。
2. **ST**：账本对每个信号记录当时的股票名称和 `is_st`。历史上这一项已用 BaoStock 的逐日 `isST` 复测过（`../2026-11-22-first-board-low-open-st/memo.md`）：328 个信号里只有 2 个是 ST，去掉后结果略好。账本规则不因此改动。
3. **头 5 分钟均价**（2026-11-22 晚加入）：账本按开盘价 + 10bp 成交，但"低开 3%–4%"要等 9:25 竞价结束才知道，最早 9:30 才能下单。账本对每笔成交记录买入日第一根不复权 5 分钟线的开盘价、均价、最高价、成交额和订单占成交额的比例（`first_5m`），并按均价买入、其余不变重算单笔净收益（`vwap_net_return`）。账本净值仍按开盘价计。已有的 4 笔已补上：均价平均比开盘价高 0.19%，按均价买入的均值是 +1.20%（开盘价口径 +1.43%）；4 笔没有统计意义。

## 预注册的复盘口径

信号每年只有 19–62 笔，攒够样本要很久。在此之前不按结果调参。

- 满 **30 笔**做第一次复盘，满 **60 笔**做第二次；不到 30 笔不下结论。
- 看四件事：
  - 单笔净收益均值是否 > 0（同一规则的回测 2020–2026 为 219 笔、均值 +1.46%、胜率 50.7%）；
  - 「源码卖点」与「收盘卖」的单笔净收益差，方向和大小；
  - ST 信号占比，以及去掉 ST 后的均值（历史上约每 160 个信号 1 个）；
  - 买入日开盘价是否真的能成交：一字跌停开盘、开盘即涨停的笔数；
  - （2026-11-22 追加，当时账本已有 4 笔成交）按头 5 分钟均价买入的单笔净收益均值是否 > 0，以及均价比开盘价高多少（历史 219 笔：均值 +0.63%，均价平均高 0.81%）。追加的原因是历史复测发现上一条在这个信号定义下恒为 0，答不了问题。
- 账本不记录也无法验证：集合竞价的实际成交量、盘口冲击。买入价假定为开盘价 + 10bp。

## 边界

- 纸面账本不是实盘业绩。开盘价成交是假设，小盘股开盘集合竞价的容量没有验证。
- 补跑的 15 个交易日是事后计算的，规则在此之前已冻结，但它们不是实时记录。
- 前复权价以最新交易日为基准，所以当日的前复权开盘/收盘价等于实际成交价；持仓期间遇到除权，账本会把持仓换算到新的价格基准（成本不变）并在运行结果的 `rebased` 里列出。
- 生产动作：none。
