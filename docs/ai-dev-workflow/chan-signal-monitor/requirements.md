# 缠论多周期股票监控需求

## 目标

为中国 A 股建立可常驻运行的自动信号系统，替代手工截图分析：自动获取分时、1/5/15/30/60/120 分钟和日线行情，识别缠论中枢及买卖点，筛选 MACD 0 轴附近金叉，并把新信号推送到用户配置的接口。

## 已确认范围与工程假设

- 市场：默认沪深 A 股，排除 ST、退市整理和上市不足 120 个交易日的股票；代码同时兼容 `000001` 与 `000001.SZ`。北交所可配置开启，但不在默认扫描范围。
- 价格口径：默认不复权（`none`），保证腾讯日线与分钟线一致。同一份多周期报告禁止混用不同复权口径；若配置 `qfq/hfq`，提供方不支持目标周期复权时该周期返回不可用，不以未复权数据冒充。数据合同记录来源、时区、复权方式和是否已收盘。
- 数据源：默认用标准库直连腾讯免费日线/分钟线，股票列表和快照使用东方财富并自动降级新浪财经；AkShare/Tushare 为可选适配。120 分钟线由 60 分钟线重采样生成。
- 扫描分层：日线任务可扫描全市场；高频多周期任务只监控自选股与候选池，避免免费接口限频和数千股票逐分钟请求不可用。
- 分时：本期定义为当日 1 分钟 OHLCV、成交额、累计 VWAP 和涨跌幅摘要，不包含 Level-2 盘口与逐笔成交；数据源缺少成交额时明确输出“典型价格近似均价”，不标为真实 VWAP。
- 缠论：采用本设计中确定性的工程化规则（包含处理、分型、笔、中枢、离开/回抽及 MACD 背驰辅助），所有参数写入配置并在信号中给出证据。
- 0 轴金叉：DIF 从不高于 DEA 转为高于 DEA，且 DIF、DEA 相对收盘价的绝对偏离均不超过配置阈值；可叠加趋势和多周期确认评分。
- 推送：企业微信、邮件、通用 HTTP Webhook；采用事务 outbox 和每通道投递状态，语义为“至少一次”。payload 带幂等键，接收方支持幂等键时可避免网络重试导致的重复。
- 系统只生成研究与提醒信号，不自动下单，不承诺收益。

## 功能需求

1. 获取并标准化 OHLCVA（开高低收量额），支持 `1m/5m/15m/30m/60m/120m/1d`。
2. 对每个周期输出：MACD、0 轴金叉/死叉、分型、笔、中枢、最新缠论买卖点。
3. 缠论买卖点至少覆盖：
   - 一类买/卖：离开最近中枢后创新低/高，同时 MACD 力度衰减。
   - 二类买/卖：一类点后的反向运动完成，再次回试但不破一类点。
   - 三类买/卖：向上/向下离开中枢后回抽不重新进入中枢。
4. 按多周期一致性计算信号分数，优先推送日线/大周期趋势同向的信号。
5. 提供单次分析、单次扫描和常驻监控命令。
6. 仅在 A 股交易时段执行分钟级监控；收盘后执行日线候选扫描。
7. SQLite 记录已发送事件，重启后仍能去重。
8. 单只股票或单周期数据失败时继续处理其他任务，并记录错误。
9. 候选池每日重算，默认保留 5 个交易日、最多 100 只，过期/停牌/退市股票自动清理。
10. 首次启动只推送在最新已完成 K 线上确认且位于新鲜窗口内的信号，不补推陈旧历史点。
11. 全市场日线首次使用可续跑的历史回填；覆盖率按成功且新鲜、至少 120 根日线的股票计算，失败股票持续重试，不能因游标走完而标记完成。完成后使用批量日行情增量维护，不再每日逐股下载全部历史。

## 非功能需求

- 数据源调用有连接/读取超时、增量缓存、供应商级最小调用间隔、指数退避、单轮时间预算与失败隔离。
- 核心策略为纯计算模块，可用固定 K 线单元测试，不依赖网络。
- 配置中的 Token、Webhook、邮箱密码允许用环境变量覆盖，示例文件不保存真实密钥。
- 输出包含风险提示、信号类型、周期、触发价格、中枢区间、MACD 与评分依据。

## 验收标准

- 固定样例可稳定识别中枢、一/二/三类买卖点和 0 轴金叉，逐根回放与全历史计算对已确认信号一致。
- 120 分钟重采样的 OHLCV 聚合正确。
- 连续执行相同 K 线不会重复发送；新 K 线上的新信号可以发送。
- 无通知配置时仍可完成分析并写入本地结果。
- `python main.py analyze --symbols ...`、`scan`、`monitor` 三种模式可由 README 指引启动。

## 明确不承诺

“0 轴金叉 + 缠论共振”在本期是候选筛选与排序规则，不声明已经提高实际胜率。验证胜率需要另行定义成交价、持有/退出规则、手续费、滑点、停牌涨跌停处理、比较基准和样本外区间并完成回测。
