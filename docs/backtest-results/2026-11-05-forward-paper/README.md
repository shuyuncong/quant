## 纸面 vs 回测的对照（2026-11-26 修正）

`tracking`（Web 页面的「纸面 vs 回测」卡片、`forward_paper.py --action status` 的输出）在 2026-11-26 之前没有在比：

- 它拿账本净值去对快照里的回测净值曲线，而那条曲线只在手动重算回测时更新，停在 2026-11-04，正好是账本的起点。账本的每一天都对到同一个点，所以回测收益恒为 0.00%，「差异」等于账本自己的收益，「跟踪误差」等于账本自己的波动。11-26 显示的 3.96% 超过了下面 2% 的门槛，但它不是跟踪误差。
- 现在每次推进后，用同一套规则把回测重算到最新交易日，存在状态目录的 `etf_paper_reference.json`。回测从账本第一个净值日之前 30 个交易日起算，本金取账本本金。快照里的回测曲线和指标不动。
- 对照从账本**首次持仓的那个净值日收盘**算起。之前的现金期不算：回测一直持仓，那几天的差只反映账本哪天开始，不是执行偏差。
- 只比两边都有的交易日，输出里的 `since` / `until` 是实际比较的起止日。对齐的交易日少于 2 个时全部为空，不再显示 0。

修正后的读数（2026-11-26 收盘）：

| 账本 | 比较区间 | 对齐日 | 纸面 | 回测 | 差异 | 跟踪误差（年化） |
|---|---|---:|---:|---:|---:|---:|
| 50 万（cron） | 11-09 → 11-26 | 14 | -1.99% | -2.00% | +0.01pp | 0.05% |
| 25 万（Web） | 11-05 → 11-26 | 16 | -1.93% | -1.98% | +0.05pp | 0.12% |

- 50 万账本的累计收益是 -2.04%，同一段时间一直持仓的回测是 -1.61%。相差的 0.44 个百分点全部来自建仓之前（11-04 收盘 → 11-09 收盘）：这三个交易日回测 +0.40%，账本 11-09 开盘才买入，只有建仓费用 -0.06%。建仓之后两者一致。
- 起算点前移多少，影响可以忽略：改成 60、120 个交易日或从行情起点（2024-03-13）算起，50 万账本的差异在 0.005–0.012pp、跟踪误差在 0.05%–0.06% 之间。
- 25 万那一行是用生产状态文件的副本和生产行情算的。生产上的对照文件由定时任务「ETF 轮动刷新」（交易日 15:35）每天重写；没有这个文件时页面显示「—」。
- 这是量法的修正，不是调参：规则、仓位、成交假设都没有动。三周的样本只说明账本在按规则执行，不说明策略好坏。

## 运行方式

```bash
# 服务器（cron，Asia/Shanghai）：30 16 * * 1-5
scripts/run_forward_paper.sh

# 只查看，不改变状态
cd quant-python/signal_system && ../.venv/bin/python forward_paper.py --action status
```

Windows 上用 `scripts/run_forward_paper.ps1 -Sync -Calendar`，效果相同。**两台机器不要同时推进同一个账本**；当前以服务器为准。

- 每次运行：同步行情 → 逐个交易日补成交/盯市 → 本周最后交易日生成下周计划。
- 幂等：重复运行不会重复成交或重复生成计划；漏跑的交易日下次自动补上。
- 同步因网络失败时 `cycle` 会明确报错，不动账本。先修数据同步，不要用旧行情或手工价格继续。
- 日志：`quant-python/signal_system/logs/forward_paper.log`。
- 失败报警：运行退出码非 0 时，把错误推送到 Web 设置页里已启用的通知渠道（当前只有 Bark）。
- 心跳：交易日 22:30，systemd 用户定时器 `quant-ledger-heartbeat.timer` 运行 `ledger_heartbeat.py`，检查这份账本、首板低开账本和 Web 的 25 万账本是否都推进到了最新交易日，落后就推送到同一组渠道。它不走 cron，所以 cron 没在跑时也会报。整台机器关机或断网时仍然没有报警。日志：`quant-python/signal_system/logs/ledger_heartbeat.log`；单元文件：`scripts/systemd/`。


## 每周节奏

1. **周五收盘后**：同步到最新交易日；若 `week_end_status` 判定为本周最后交易日，生成下周计划。
2. **下一交易日开盘**：`fill_paper` 按开盘价成交；卖出先于买入，整手 100，佣金 3bp（最低 5 元），滑点 5bp。
3. **每个交易日**：`mark_paper_to_market` 更新净值；不因盘中波动改计划。
4. **周末**：记录 `tracking_error_pct`、成交滑点、现金/整手、未成交原因、信号日/成交日。

## 预注册的复盘指标

6–12 个月后统一看，不中途按结果调参：

- 纸面账本 vs canonical 回测的跟踪误差；
- 实际成交价 vs 信号日收盘/次日开盘的偏差；
- 现金、整手、最低佣金造成的拖累；
- 未成交/跳过订单的原因；
- 与 `execution_stress` 的 5/10/20bp 价差情景对比。

建议的“可接受”门槛（研究用，不是生产 SLA）：

- 跟踪误差 ≤ 2%/年；
- 无法解释的现金/整手差异 = 0；
- 成交滑点落在已测压力区间内；
- 没有“无记录”的订单。

## 边界

- 纸面账本不是实盘 track record，不证明未来收益。
- V5 的折溢价/盘口/部分成交仍没有真实数据；纸面账本只记录实际可观察的成交假设。
- V4 的 PIT 退市池仍未关闭；当前池是当前上市 ETF，幸存者偏差未消除。
- 生产动作：none。
