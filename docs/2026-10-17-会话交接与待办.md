### 3. 行尾统一（本会话最后一项，已完成）
- 实测：`text=auto` 只改仓库不改检出（Windows 仍 CRLF）；**必须 `eol=lf`**（优先级高于 `core.autocrlf`）。
- 执行：`.gitattributes` + 278 个文件重写 → **277 → 1 个 CRLF**（剩的是有意排除的）。
  已跟踪文件**内容零改动**。
- **全新克隆验证**：`autocrlf=true` 与 `false` 两种配置检出**都得到 LF** → 平台差异消除。
- 字节保真：`-text` 的 CSV 与两个二进制 sha256 完全一致。
- **过程失误（已修）**：初版 glob `docs/backtest-results/**/*.csv -text` 方向相反，把 CRLF 写进了索引 → 收窄为单文件。

### 4. 成交量契约转绿
- 定位**两个独立原因**：① 常量登记自 **CRLF** 工作区（`488f91c4…` 实测 = `7835a04` 的 CRLF 形态）；
  ② 该常量记的是旧版本（其后该文件又改过数次）。
  冒烟证据：同文件内 `config.yaml` 的常量按 LF 登记、`market_data.py` 的按 CRLF 登记。
- 修法：新增 `source_text_sha256()`（`\r\n`→`\n` 再算哈希，**仅用于文本源码**）+
  重登记为 `530b37c9f2507b1d…`。**刻意不动** `candidate_integrity.file_sha256`（比对数据文件）。
- 验证：LF **37 passed**；**人为改 CRLF 仍 37 passed**（行尾免疫）；注入内容改动 **1 failed**（仍有牙齿）；
  全量 **1435 passed / 0 failed**（原 1434/1）。

**铁律**
- 生产配置**严禁未经确认改动**（本次全程未改配置）。
- 判断策略是否在生产：**只看调用图，不看 docstring**。
- 给运维的命令必须**单行、且本地实测出期望输出**（超 ~80 字符即拆）。
- 一次性脚本用完即删；结论固化到 docs。
- 预登记哈希常量是**完整性契约**，改动须附登记注释。
- `cache`/`output` 在 git 中 **0 个被跟踪文件**。
- 提交信息须如实记录"依据不足"与"哪些 bug 是本会话引入的"。

**环境坑**
- 容器内 Python 不在 PATH（仅 `/opt/venv/bin/python`）→ 脚本读 `PYTHON_BIN`。
- 本机 `curl` 损坏（libcurl error 43）→ 用 Python `urllib.request` 或浏览器。
- 多行中文 heredoc 嵌套引号易 `SyntaxError` → 用 `write` 落成文件再执行。
- Node `--env-file-if-exists` **不覆盖已存在的 shell 变量**（实测）→ 可用 `DATABASE_URL=… npm run …` 临时切库。
- `npm run db:tunnel` **不是** `ssh -L` 的替代（HTTP CONNECT 代理，端口 15432，会被守卫拒）。
- 守卫白名单仅 `localhost`/`127.0.0.1`/`::1` 三个字符串 —— **内网 IP 也被拒**。
