# Mac 开发机接入家庭服务器 Postgres —— 操作单

日期：2026-10-16
方案：**②**（家庭服务器装 PG，Mac 经 SSH 隧道接入；全内网，不过公网）
前置阅读：`docs/2026-10-16-开发机数据库访问边界.md`

## 0. 一个关键认知：**PG 不需要监听局域网**

这是本方案最容易被做错、也最值得强调的一点。

`ssh -L 5432:127.0.0.1:5432 <家庭服务器>` 的含义是：

> **由 SSH 服务端（家庭服务器）去连 `127.0.0.1:5432`**，把结果转发到 Mac 的 `5432`。

所以家庭服务器上的 Postgres **只需要监听 `127.0.0.1`** ——
**不用改 `listen_addresses`、不用加 `pg_hba.conf` 的局域网规则、不用开防火墙端口**。
数据库始终只绑在本机回环上，局域网里其它机器**根本连不上它**。

这比"把 PG 暴露到内网"安全得多，而且步骤更少。

## 1. 家庭服务器：装 PG 并建库（一次性）

### 1.1 安装（按发行版选一条）

```bash
# Debian / Ubuntu
sudo apt update && sudo apt install -y postgresql
```

```bash
# Fedora / RHEL 系
sudo dnf install -y postgresql-server && sudo postgresql-setup --initdb
```

```bash
# Arch
sudo pacman -S --noconfirm postgresql && sudo -iu postgres initdb -D /var/lib/postgres/data
```

装完确认版本。**建议与服务端已有环境一致（16.x）**，避免 `jsonb`/`regexp_replace` 行为差异：

```bash
sudo -u postgres psql -tAc "SHOW server_version"
```

期望：`16.x`（或更高；本项目在 16 上验证过）。

### 1.2 建用户与库

本项目要求**库名必须是 `quant`**（`assertLocalDevelopmentDatabase` 硬校验库名与端口）：

```bash
sudo -u postgres createuser -s quant
```

```bash
sudo -u postgres createdb -O quant quant
```

```bash
sudo -u postgres psql -c "ALTER USER quant PASSWORD '换成你的密码'"
```

> `-s`（superuser）是为了让 `npm run db:setup` 能建 schema。
> 生产用的是最小权限角色（`quant_owner`/`quant_app`/`quant_backup`），
> **开发库不需要那套**，见 §1.4。

### 1.3 确认只监听回环

```bash
sudo -u postgres psql -tAc "SHOW listen_addresses"
```

期望：`localhost`（Debian/Ubuntu 默认）。若是 `*`，改成 `localhost` 并重启：

```bash
sudo sed -i "s/^listen_addresses.*/listen_addresses = 'localhost'/" /etc/postgresql/*/main/postgresql.conf
```

```bash
sudo systemctl restart postgresql
```

**注意**：不要改成内网 IP。§0 说了，隧道模式下不需要。

### 1.4 不需要建 `quant_app` / `quant_backup` 角色

`schema.sql` 里的角色授权块**只在角色已存在时生效**（源码注释原文：
"本块只做授权，且仅在角色已存在时生效，避免未初始化环境 DDL 失败"）。
创建角色的通道 `QUANT_SETUP_ROLES=1` 会先过一道门禁，**只允许 `quant-db` 或 loopback**。
开发库用不上，**直接跳过**即可。

### 1.5 确认 SSH 可从 Mac 连上

```bash
# 在 Mac 上
ssh <用户>@192.168.x.x "echo ok"
```

期望：`ok`。连不上就先解决 SSH（交换机/防火墙/服务是否在跑），**与 PG 无关**。

建议配免密（后面隧道要长期开着，否则每次都要输密码）：

```bash
ssh-keygen -t ed25519 -C "mac-dev" -f ~/.ssh/id_ed25519
```

```bash
ssh-copy-id <用户>@192.168.x.x
```

## 2. Mac：起隧道

```bash
ssh -N -L 5432:127.0.0.1:5432 <用户>@192.168.x.x
```

- `-N`：不执行远端命令，只转发
- 这个窗口**要保持开着**；关掉隧道即断
- 首次会问指纹，接受即可

**验证隧道通了**（另开一个 Mac 终端）：

```bash
psql "postgresql://quant:<密码>@127.0.0.1:5432/quant" -tAc "SELECT 1"
```

期望输出：`1`。若报 `could not connect`，看隧道窗口有没有报错。

> **Mac 上没有 `psql`？** 用 `brew install libpq` 再
> `brew link --force libpq`，或者先跳过这步，用 §3.2 的 `db:verify` 验证。

## 3. Mac：配置并初始化

### 3.1 准备 `.env.local`

位置：`quant-python/web/.env.local`（已在 `.gitignore` 里，不会提交）

```
DATABASE_URL=postgresql://quant:<密码>@127.0.0.1:5432/quant
DATABASE_SSL_MODE=disable
SCHEDULER_DISABLED=1
```

三点说明：

- **`127.0.0.1` 是必需的**，不能写 `192.168.x.x` —— 守卫白名单只有
  `localhost/127.0.0.1/::1` 三个字符串，内网 IP 会被拒（已实测）。
- `DATABASE_SSL_MODE=disable` 严格说可省（`db.ts:58` 见 loopback 会自动关 TLS），
  但显式写上更清楚。
- `SCHEDULER_DISABLED=1` 按 `.env.example` 的建议：
  "共享数据库时只要线上一个实例跑调度器，本地不参与"。
  本方案里 Mac 用的是独立开发库，不设也不会冲突；
  但**若以后你让 Windows 与 Mac 指向同一个库**，这一个必须设，
  否则两个调度器会同时发通知。

### 3.2 建 schema 并验证

```bash
cd quant-python/web && npm ci
```

> 用 **`ci`** 而不是 `install` —— 保证与 `package-lock.json` 完全一致
> （本会话踩过：漏更 lock 文件导致构建不一致）。

```bash
npm run db:setup
```

期望（`schema_version` 必须是 **5**）：

```json
{"schema_version":5,"current_user":"redacted","tables":["analysis_notes",...13 张...]}
```

```bash
npm run db:verify
```

期望：包含 `"transaction_round_trip":true`、`"public_schema_usage":false`，
且 counts 里有一批表名（新库都是 0）。

> `db:setup` / `db:verify` **不受** loopback 守卫限制
> （只有 `npm run dev` 与 `db:migrate` 受限制），所以即使隧道没通、
> 你临时直连内网也能建 —— 但 `npm run dev` 必须走隧道。

### 3.3 启动开发服务

```bash
npm run dev
```

期望：日志里出现 Next.js 启动信息，**不出现** `[database] 拒绝启动`。
服务在 `http://127.0.0.1:3111`（`dev.mjs:26` 写死 `-H 0.0.0.0 -p 3111`）。

浏览器打开 `http://127.0.0.1:3111/results`，能看到页面即成功。

## 4. 让隧道开机自启（可选，但强烈建议）

Mac 上用手册 `launchd`（不需装任何东西）：

```bash
mkdir -p ~/Library/LaunchAgents
```

把下面内容存为 `~/Library/LaunchAgents/com.quant.dbtunnel.plist`
（**替换 `用户名`、`192.168.x.x`**）：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
  <key>Label</key><string>com.quant.dbtunnel</string>
  <key>ProgramArguments</key>
  <array>
    <string>/usr/bin/ssh</string>
    <string>-N</string>
    <string>-o</string><string>ExitOnForwardFailure=yes</string>
    <string>-o</string><string>ServerAliveInterval=30</string>
    <string>-o</string><string>ServerAliveCountMax=3</string>
    <string>-L</string><string>5432:127.0.0.1:5432</string>
    <string>用户名@192.168.x.x</string>
  </array>
  <key>RunAtLoad</key><true/>
  <key>KeepAlive</key><true/>
  <key>StandardOutPath</key><string>/tmp/quant-dbtunnel.log</string>
  <key>StandardErrorPath</key><string>/tmp/quant-dbtunnel.err</string>
</dict>
</plist>
```

加载：

```bash
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.quant.dbtunnel.plist
```

`KeepAlive` 会在断线后自动重连，`ServerAliveInterval` 防止 NAT 把空闲连接掐掉 ——
这两条就是为了解决"隧道悄悄断了、dev 卡住"。

## 5. 验收清单

| # | 检查 | 命令 | 期望 |
|---|---|---|---|
| 1 | 内网可达 | `ping -c1 192.168.x.x` | 有回应 |
| 2 | SSH 通 | `ssh <用户>@192.168.x.x "echo ok"` | `ok` |
| 3 | PG 只绑回环 | 服务器上 `SHOW listen_addresses` | `localhost` |
| 4 | 端口占用 | Mac 上 `lsof -nP -iTCP:5432 -sTCP:LISTEN` | 只有 `ssh` |
| 5 | 隧道可用 | `psql ...@127.0.0.1:5432/quant -tAc "SELECT 1"` | `1` |
| 6 | schema 版本 | `npm run db:verify` | `Schema version must be 5` 不报错 |
| 7 | 开发服务 | `npm run dev` | 无 `[database] 拒绝启动` |
| 8 | 页面 | 打开 `/results` | 正常渲染 |

## 6. 已知坑

| 症状 | 原因 | 处理 |
|---|---|---|
| `[database] 拒绝启动：非本地主机 "192.168.x.x"` | 直接写了内网 IP | 必须写 `127.0.0.1` 并起隧道 |
| `[database] 拒绝启动：非本地主机 "home.lan"` | 同上（主机名也不行） | 同上 |
| `bind: Address already in use`（起隧道时） | Mac 上已有进程占 5432（如别的 PG） | `lsof -nP -iTCP:5432` 找出来，先停掉 |
| `npm run dev` 起来但页面转圈/报连接超时 | 隧道断了 | 看 launchd 日志 `/tmp/quant-dbtunnel.err`；`db.ts` 的连接超时是 15s |
| `Schema version must be 5` | `db:setup` 没跑或跑在别处 | 重跑 `db:setup`，确认它连的是同一个 `DATABASE_URL` |
| 页面上数据"像生产" | 以为连了生产 | 守卫已确保不可能；这是你自己开发库里的数据（可用 dump 灌过） |

## 7. 这个方案的代价（明确写下）

**Mac 必须能连回家庭服务器**，因此：

- 家里断电/断网/服务器重启 → 无法开发（`npm run dev` 起不来）
- 把 Mac 带出门（咖啡厅/出差）→ 需要 VPN 回家，否则无法开发
- 家里路由换网段 → 要改 `~/.ssh/config` 或 plist 里的地址

**如果这些不可接受**，改用 Mac 本机 PG（Homebrew `postgresql@16`），
完全不依赖网络 —— 见 `docs/2026-10-16-开发机数据库访问边界.md` 的 A1。
两条路的取舍只有这一点，其余（安全、步骤量、Mac 资源占用）差别都很小。
