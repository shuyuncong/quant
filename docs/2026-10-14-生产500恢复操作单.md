# 生产 500 恢复操作单（2026-10-14）

## 结论：库停在 v4、代码要 v5

日志里的决定性一行：

```
Error: An error occurred while loading instrumentation hook:
Unsupported quant database schema version: 4. Run npm run db:setup.
```

- `quant-python/web/src/lib/db.ts` 的 `SCHEMA_VERSION = 5`
- 生产库 `quant.schema_meta` 里最高版本是 **4**
- 两者不等 → `validateSchema()` 在 **instrumentation hook** 抛错 → Next 进程起不来
  → **整站 500，连 `/logo.svg` 都 500**（静态资源也先过 instrumentation）
- 容器状态 `Up (unhealthy)`、`HTTP 500`、nginx `Empty reply` 都由此解释

v5 是 `580c875 feat(web): 持仓归属策略字段（schema v5 + 表单 + 接口）`（2026-10-12）引入的，
只差一步「在服务器上执行迁移」。

## 为什么自动部署没做迁移

`deploy-quant.sh` 的顺序是：**先 `up -d --build` 重建容器，再跑 `db:setup`**。
迁移那一步有前置条件：

```bash
OWNER_PASSWORD="$(get_env PG_OWNER_PASSWORD)"
if [ -z "$OWNER_PASSWORD" ]; then
    log "ERROR: 未找到 PG_OWNER_PASSWORD，跳过迁移（后续页面会 500，请手动执行 db:setup）"
```

你自己那条 `db:verify` 已经证实了这一点：

```
Error: SASL: SCRAM-SERVER-FIRST-MESSAGE: client password must be a string
```

`${PG_OWNER_PASSWORD}` 在本机 shell 里是**空的**，所以脚本那一步同样跳过了。
**新容器已经起来，迁移没跑** → 就成了现在这个状态。

## 恢复：三步

### 第 1 步：看 .env 里有没有这个变量

```bash
cd /opt/docker/quant/quant-python/quant-python
grep -nE '^[[:space:]]*(DB_MODE|PG_OWNER_PASSWORD|PG_APP_PASSWORD)=' .env | sed -E 's/(PASSWORD=).*/\1***/'
```

- **有输出** → 进第 2 步（我给的命令会把值读进来）
- **只有 DB_MODE、没有 PG_OWNER_PASSWORD** → 跳到「情况 B」

### 第 2 步：执行迁移（幂等，可重复跑）

```bash
PG_OWNER_PASSWORD="$(sed -n 's/^[[:space:]]*PG_OWNER_PASSWORD[[:space:]]*=[[:space:]]*\([^#[:space:]]*\).*/\1/p' .env | tail -n1)"

if [ -z "$PG_OWNER_PASSWORD" ]; then
  echo "!! .env 里没有 PG_OWNER_PASSWORD，不要继续，先看情况 B"
else
  docker exec \
    -e "DATABASE_URL=postgresql://quant_owner:${PG_OWNER_PASSWORD}@quant-db:5432/quant" \
    -e DATABASE_SSL_MODE=disable \
    quant-web npm run db:setup

  docker restart quant-web
fi
```

> 用 `sed` 单独取值、不用 `source .env`：compose 的 dotenv 不是 shell 语法，
> 整文件 source 可能被特殊字符/命令替换影响（部署脚本的注释里也说明了这一点）。

### 第 3 步：验证

```bash
sleep 15
docker ps --filter name=quant-web --format '{{.Names}}\t{{.Status}}'
curl -sS -o /dev/null -w 'origin %{http_code}\n' http://127.0.0.1:3111/
curl -sS -o /dev/null -w 'nginx  %{http_code}\n' http://127.0.0.1/
```

期望：`Up (healthy)`、两个都 `200`。

再确认版本已对齐：

```bash
docker exec -e DATABASE_URL="postgresql://quant_owner:${PG_OWNER_PASSWORD}@quant-db:5432/quant" \
  -e DATABASE_SSL_MODE=disable quant-web npm run db:verify
```

## 情况 B：.env 里确实没有 PG_OWNER_PASSWORD

**别去猜密码。** `quant_owner` 的密码当年只在初始化时设置过一次，猜错会白折腾。
两个方向：

**B-1（推荐）** 去服务器上的备份里找。备份脚本是 `docs/ops/backup-quant.sh`，
它连库时必然带 owner 凭据：

```bash
grep -nE 'PG_OWNER_PASSWORD|PGPASSWORD|postgresql://' /home/ubuntu/ops/backup-quant.sh | sed -E 's/(:)[^:@]+(@)/\1***\2/'
```

或在 `.env` 的历史副本里找：

```bash
ls -la .env* ; grep -l PG_OWNER_PASSWORD .env* 2>/dev/null
```

**B-2** 确认 `.env` 里其实有，只是名字不同（例如 `PG_PASSWORD` / `POSTGRES_PASSWORD`）：

```bash
grep -inE 'password' .env | sed -E 's/(=).*/\1***/'
```

找到后把它加进 `.env`（**不要**提交进 git，`.env` 应在 gitignore 内）：

```bash
echo 'PG_OWNER_PASSWORD=<找到的值>' >> .env
```

然后回第 2 步。

## 临时止血（只想先让站点活过来）

如果第 1 步发现没密码、又一时找不到，可以让**旧代码**先跑：

```bash
cd /opt/docker/quant/quant-python
git log --oneline -10                     # 找到 580c875 之前那个提交
git checkout <上一个提交>                  # 例如 580c875~1
cd quant-python
docker compose -f docker-compose.oracle.yml -f docker-compose.oracle.db.yml up -d --build
```

⚠️ 注意：`SCHEMA_VERSION` 是**前向只增**的。旧代码（期望 v4）配 v4 库能跑；
但如果迁移已经成功跑过（库到 v5），旧代码反而会因"版本 5 ≠ 4"起不来。
所以：**要么迁移 + 新代码，要么回退代码 + 保持库在 v4**，不要交叉。

## 已做的防复发改动

`docs/ops/deploy-quant.sh` 现在在**重建容器之前**就校验 `PG_OWNER_PASSWORD`：

```bash
if [ "$DB_MODE" = "selfhost" ] && [ -z "$(get_env PG_OWNER_PASSWORD)" ]; then
    log "ERROR: DB_MODE=selfhost 但 .env 缺少 PG_OWNER_PASSWORD，无法执行 db:setup，中止部署（旧容器继续服务）"
    exit 1
fi
```

改成 fail-closed：宁可部署不动、旧容器继续服务，也不要"重建完才发现迁移跑不了"
把整站打挂。原行为只打一行日志就继续，这正是本次事故的成因。
确需跳过时用 `DEPLOY_PAUSED=1`（脚本里已有该出口）。
