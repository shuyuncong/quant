## 1. 系统概述

### 1.1 系统定位

量化交易信号系统第一阶段是一个**纯信号提示系统**，核心目标是：
- 自动化选股和信号生成
- 提供精确到分钟级的交易信号
- 通过通知推送，无需实时盯盘
- 为后续可视化和回测系统提供数据基础

### 1.2 核心特性

- ✅ **日线级选股**: 每日收盘后筛选符合条件的股票池
- ✅ **分钟级信号**: 对入选股票进行 5/30/60/120 分钟级别监控
- ✅ **模块化策略**: 支持多种策略灵活组合
- ✅ **智能通知**: 企业微信/邮件推送关键信号
- ✅ **数据缓存**: 减少 API 调用，提高响应速度

### 1.3 非目标（第一阶段不做）

- ❌ 自动交易执行
- ❌ Web 可视化界面
- ❌ 回测功能
- ❌ 持仓管理
- ❌ 绩效分析

### 2.2 分层架构

#### 2.2.1 数据层 (Data Layer)

**职责**: 数据获取、存储、管理

**核心模块**:
- `DataFetcher`: 数据获取器
  - Tushare API 封装
  - 多数据源支持（预留 AkShare 等）
  - 智能缓存机制
  - 错误重试和降级

- `DataCache`: 数据缓存
  - 日线数据缓存（24 小时）
  - 分钟数据缓存（6 小时）
  - 财务数据缓存（7 天）
  - LRU 淘汰策略

- `DataCleaner`: 数据清洗
  - 异常值处理
  - 缺失值填充
  - 数据标准化

#### 2.2.2 策略层 (Strategy Layer)

**职责**: 策略计算、信号生成

**核心模块**:
- `StockSelector`: 选股引擎
  - 基本面筛选器
  - 技术面初筛器
  - 成交量筛选器
  - 多条件组合

- `SignalEngine`: 信号引擎
  - 技术指标计算
  - 信号识别
  - 信号评分
  - 信号过滤

- `StrategyManager`: 策略管理器
  - 策略注册
  - 策略组合
  - 策略切换
  - 参数管理

#### 2.2.3 服务层 (Service Layer)

**职责**: 通知、日志、存储

**核心模块**:
- `Notifier`: 通知服务
  - 企业微信推送
  - 邮件推送
  - 消息格式化
  - 推送队列

- `Logger`: 日志服务
  - 分级日志
  - 文件轮转
  - 异常追踪

- `Storage`: 存储服务
  - 信号历史
  - 选股记录
  - 运行日志

## 3. 核心流程

### 3.1 日线选股流程

```
每日 15:30 触发
    ↓
获取全市场股票列表 (5000+)
    ↓
基本面筛选
├─ ROE > 10%
├─ 负债率 < 50%
├─ PE < 30
└─ 市值 50-500 亿
    ↓ (~500 只)
成交量筛选
├─ 换手率 1-5%
└─ 流动性充足
    ↓ (~200 只)
技术面初筛
├─ 年线方向
├─ 价格位置
└─ MACD 状态
    ↓ (~50 只)
生成候选股票池
    ↓
保存到缓存
    ↓
推送选股结果
```

### 3.2 分钟级信号流程

```
交易时间内每 N 分钟触发
    ↓
从缓存读取候选股票池
    ↓
获取分钟级行情数据
├─ 5 分钟 K 线
├─ 30 分钟 K 线
├─ 60 分钟 K 线
└─ 120 分钟 K 线
    ↓
计算技术指标
├─ MACD
├─ 均线
├─ RSI
├─ 背离检测
└─ 量价关系
    ↓
信号识别
├─ 买入信号
│   ├─ 底背离 + 放量
│   ├─ MACD 金叉
│   └─ 回调至支撑位
└─ 卖出信号
    ├─ 顶背离
    ├─ MACD 死叉
    └─ 破位下跌
    ↓
信号评分和过滤
├─ 评分 > 阈值
├─ 去重（同一股票多周期）
└─ 优先级排序
    ↓
推送高优先级信号
```

### 3.3 市场环境判断流程

```
获取上证指数数据
    ↓
计算技术指标
├─ 250 日均线
├─ MACD
└─ 成交量
    ↓
判断市场状态
├─ 牛市: MA250↑ + 价格>MA250 + MACD>0
├─ 熊市: MA250↓ + 价格<MA250 + MACD<0
└─ 震荡: 其他情况
    ↓
调整策略参数
├─ 牛市: 激进参数
├─ 熊市: 保守参数
└─ 震荡: 中性参数
```

## 7. 性能设计

### 7.1 性能目标

| 指标 | 目标值 |
|------|--------|
| 日线选股耗时 | < 5 分钟 |
| 分钟信号计算 | < 30 秒 |
| 通知推送延迟 | < 5 秒 |
| 缓存命中率 | > 80% |
| 系统可用性 | > 99% |

### 7.2 性能优化策略

#### 7.2.1 数据层优化

- **缓存优先**: 优先使用缓存数据
- **批量获取**: 批量请求减少 API 调用
- **并发处理**: 多线程/多进程处理
- **增量更新**: 只更新变化的数据

#### 7.2.2 计算层优化

- **向量化计算**: 使用 numpy/pandas 向量化
- **预计算**: 提前计算常用指标
- **懒加载**: 按需加载数据
- **结果缓存**: 缓存计算结果

#### 7.2.3 通知层优化

- **异步推送**: 非阻塞推送
- **批量推送**: 合并多个信号
- **限流控制**: 避免频繁推送

## 8. 可靠性设计

### 8.1 异常处理

```python
# 三层异常处理
try:
    # 业务逻辑
    result = fetch_data()
except DataSourceError as e:
    # 数据源异常 -> 降级到备用源
    result = fetch_from_backup()
except NetworkError as e:
    # 网络异常 -> 重试
    result = retry_with_backoff()
except Exception as e:
    # 未知异常 -> 记录日志并告警

    send_alert()
```
