## 1. 你的两个方案：技术上都能通，但**都违反既定设计**

### 先讲清守卫的真实机制（这决定了"能不能通")

`assertLocalDevelopmentDatabase`（`db-safety.mjs:34-46`）**只检查 URL 字符串**：

```js
if (!isLocalDatabaseHost(location.host)) throw ...   // localhost / 127.0.0.1 / ::1
if (location.port !== "5432" || location.database !== "quant") throw ...
```

**它不做真实 TCP 对端校验** —— 不查 `pg_stat_activity.client_addr`，不验服务端证书。
所以：

| URL | 结果 |
|---|---|
| `postgresql://…@127.0.0.1:5432/quant` | ✅ 通过 |
| `postgresql://…@192.168.1.50:5432/quant`（家庭服务器局域网 IP） | ❌ 主机名拒绝 |
| `postgresql://…@home.example.com:5432/quant` | ❌ 主机名拒绝 |
| `postgresql://…@localhost:15432/quant`（隧道映到非 5432） | ❌ 端口拒绝 |

**关键**：把远端库经由隧道/relay 映到本机 **`127.0.0.1:5432`**，
URL 串与"本地 docker PG"**完全一样**，守卫**无法区分**：

```
家庭服务器 relay -> 127.0.0.1:5432/quant  ✅ 通过
生产 CF tunnel   -> 127.0.0.1:5432/quant  ✅ 通过
本地 docker PG   -> 127.0.0.1:5432/quant  ✅ 通过   ← 同一串 URL
```

所以技术上门都开着。**但"能过守卫"不等于"符合设计"**：

### 方案 A：家庭服务器装 Postgres，Mac 连它

**先更正我上一条的越界判断**：我说它"与既定隔离思路相冲突"——**这话说过头了**。
`自建数据库切换方案.md:363` 禁的是"**生产库**公网/局域网可达路径"。
家庭服务器上另起一个**开发库**不是生产库，**不违反该政策**。
（该政策的本意是隔离生产数据，不是禁止你自建开发库。）

**技术上的硬约束只有一条**：`dev.mjs` 的 `loopback` 断言。实测：

| 连法 | 守卫 |
|---|---|
| `192.168.1.50:5432/quant`（直连内网 IP） | ❌ 拒绝：非本地主机 |
| `home.illsky.com:5432/quant`（直连域名） | ❌ 拒绝：非本地主机 |
| **`127.0.0.1:5432/quant`（先建隧道再连本机）** | ✅ **通过** |

所以做法是**在 Mac 上建一条隧道**，把家庭服务器的 5432 映到 Mac 的
`127.0.0.1:5432`。**macOS 自带 OpenSSH，不需要装任何东西**：

```bash
# Mac 上，保持这个窗口开着
ssh -N -L 5432:127.0.0.1:5432 <你在家庭服务器的用户名>@<家庭服务器地址>
```

然后 Mac 的 `.env.local` 照旧写：

```
DATABASE_URL=postgresql://quant:<密码>@127.0.0.1:5432/quant
DATABASE_SSL_MODE=disable
```

`npm run dev` 就会放行 —— 守卫只比对 URL 串，看不出对端其实是家庭服务器。

**家庭服务器侧**初始化（一次性）：

```bash
sudo -u postgres createuser -s quant
sudo -u postgres createdb -O quant quant
# 在家庭服务器上只监听本机/内网，别开公网
```

`db:setup` / `db:verify` **不受** loopback 约束（只有 `npm run dev` 和 `db:migrate` 受约束），
可以直接对家庭服务器跑，把 schema 建到 v5。

**这个方案的唯一实质代价：Mac 变成"必须能连回家庭服务器"**，也就是
**笔记本失去离线开发能力** —— 换了地方/家里断网/服务器重启，`npm run dev` 就起不来。
Mac 是笔记本的话，这是主要缺点。其余都还好：
LAN 上延迟可忽略；数据集中在你已有的家庭备份体系里；Mac 不占磁盘和内存。

**安全提醒**：走 `ssh -L` 时凭据在 SSH 隧道内加密，安全。
**不要**用未加密的 `socat`/裸端口转发直连公网 —— 那样 PG 密码是明文过网。

### 方案 B：Cloudflare Tunnel 打通生产库
- 技术上：`cloudflared` 把 `quant-db:5432` 暴露到公网/或本机 loopback → 守卫能过
- **但这是明确禁止的**：`:363` 写的是"**不提供生产库公网/局域网可达路径**"
- **真实风险，且不是理论风险**：`quant.model_profiles.api_key` 存的是**明文 API key**
  （`db/schema.sql:19`）。开发机一旦能写生产库，一个误操作就能覆盖
  `settings`/`model_profiles`/`holdings`/`stock_pool`（本会话我已经在本地库里
  误插过测试行——同理的事在生产上代价完全不同）。
- 而且 `dev.mjs` 会**写库**（调度器、任务、分析记录），不是只读。

**结论：两个方案都能绕过守卫，但方案 B 违反明文设计且风险实在；方案 A 可行但没必要。**

## 2. 为什么你不需要这两个方案：**不装 Docker 也能有本地 PG**

你的约束是"不想在 Mac 上装 Docker"，不是"不能装 Postgres"。两者可以解耦：

| 方式 | 是否需要 Docker | 端口 | 守卫 |
|---|---|---|---|
| Homebrew `postgresql@16` | ❌ 不需要 | 默认 5432 | ✅ 原生通过 |
| Postgres.app | ❌ 不需要 | 5432 | ✅ |
| OrbStack / colima | 需要（轻量替代） | 5432 | ✅ |

**Homebrew 方式（Mac 原生，无 Docker）：**

```bash
brew install postgresql@16
brew services start postgresql@16          # 监听 127.0.0.1:5432
createuser -s quant                        # 或按 .env 的用户名
createdb -O quant quant
cd quant-python/web && npm run db:setup    # 建到 schema v5
npm run db:verify
```

**注意**：`assertLocalDevelopmentDatabase` 要求**库名必须是 `quant`、端口必须是 `5432`**。
Homebrew Postgres 默认就是 5432；若与已有实例冲突（比如你 Mac 上先装了别的版本），
要显式改回 5432，否则 `dev.mjs` 拒绝启动。

这样 Mac 上：**无 Docker、无隧道、无共享库**，守卫原生通过，完全符合既有设计。

## 3. 那"Mac 要用生产数据联调"怎么办 —— 走既定的离线导出

`:364` 给的路径本来就是给这个场景的：

1. 服务器每日备份已产出 `quant-db_YYYYMMDD_HHMMSS.dump`（`backup-quant.sh`，
   并已验证 `pg_restore --list` 可读）
2. 取回：`scp` 或 **R2**（`rclone copy r2-oracle-backup:oracle-backup/quant/<日期>/ …`）
3. 本地导入：`db:setup` 建 schema（v5）→ `pg_restore --data-only` 灌数据

**安全提示**：dump 里含 `model_profiles.api_key`（**明文**）。这台 dump 别随手放在
共享目录/云盘；导入后也建议把本地那个 `api_key` 换成占位值，避免本地泄露扩散。

## 4. 两台机器的一致性怎么保证

既然不共享库，就要接受"两台数据不同步"，靠这三条控制：

1. **代码**：git（已如此）
2. **schema**：两台都跑 `db:setup`，都到 v5（**本会话刚发现 Windows 那台停在 v4**，
   已修；Mac 新装务必确认 `schema_meta` 到 5）
3. **配置类数据**（`settings`/`model_profiles`/`stock_pool`/`holdings`）：
   要么各配各的，要么用 dump 一次性拉齐。**不要**试图双向同步 —— 会冲突且无仲裁
