## 运行方式

```bash
# 服务器（cron，Asia/Shanghai）：30 16 * * 1-5
scripts/run_forward_paper.sh

# 只查看，不改变状态
cd quant-python/signal_system && ../.venv/bin/python forward_paper.py --action status
```

Windows 上用 `scripts/run_forward_paper.ps1 -Sync -Calendar`，效果相同。**两台机器不要同时推进同一个账本**；当前以服务器为准。

- 每次运行：同步行情 → 逐个交易日补成交/盯市 → 本周最后交易日生成下周计划。
- 幂等：重复运行不会重复成交或重复生成计划；漏跑的交易日下次自动补上。
- 同步因网络失败时 `cycle` 会明确报错，不动账本。先修数据同步，不要用旧行情或手工价格继续。
- 日志：`quant-python/signal_system/logs/forward_paper.log`。
- 失败报警：运行退出码非 0 时，把错误推送到 Web 设置页里已启用的通知渠道（当前只有 Bark）。cron 本身没在跑时不会有报警。


## 每周节奏

1. **周五收盘后**：同步到最新交易日；若 `week_end_status` 判定为本周最后交易日，生成下周计划。
2. **下一交易日开盘**：`fill_paper` 按开盘价成交；卖出先于买入，整手 100，佣金 3bp（最低 5 元），滑点 5bp。
3. **每个交易日**：`mark_paper_to_market` 更新净值；不因盘中波动改计划。
4. **周末**：记录 `tracking_error_pct`、成交滑点、现金/整手、未成交原因、信号日/成交日。

## 预注册的复盘指标

6–12 个月后统一看，不中途按结果调参：

- 纸面账本 vs canonical 回测的跟踪误差；
- 实际成交价 vs 信号日收盘/次日开盘的偏差；
- 现金、整手、最低佣金造成的拖累；
- 未成交/跳过订单的原因；
- 与 `execution_stress` 的 5/10/20bp 价差情景对比。

建议的“可接受”门槛（研究用，不是生产 SLA）：

- 跟踪误差 ≤ 2%/年；
- 无法解释的现金/整手差异 = 0；
- 成交滑点落在已测压力区间内；
- 没有“无记录”的订单。

## 边界

- 纸面账本不是实盘 track record，不证明未来收益。
- V5 的折溢价/盘口/部分成交仍没有真实数据；纸面账本只记录实际可观察的成交假设。
- V4 的 PIT 退市池仍未关闭；当前池是当前上市 ETF，幸存者偏差未消除。
- 生产动作：none。
