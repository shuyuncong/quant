# 总体设计

## 设计原则

系统采用“全市场低频筛选 + 候选池高频监控”。这是免费行情接口下兼顾覆盖率和及时性的关键边界：全市场逐分钟抓取七个周期既容易被限流，也无法保证一轮扫描在下一分钟前结束。

## 数据流

```text
腾讯/东方财富/新浪/AkShare/Tushare -> 标准化与缓存 -> 日线全市场初筛 -> 候选池
                                           |
自选股 + 候选池 -> 多周期行情 -> MACD/缠论分析 -> 多周期评分
                                           |
                                  事件去重(SQLite)
                                           |
                         企业微信/邮件/通用 Webhook + JSON/YAML
```

## 模块边界

- `data/market_data.py`：数据源适配、代码转换、OHLCV 标准化、周期重采样和缓存。
- `strategy/macd.py`：无 TA-Lib 依赖的 EMA/MACD 与 0 轴交叉识别。
- `strategy/chan.py`：包含 K 线、分型、笔、中枢与一二三类买卖点。
- `strategy/multi_timeframe.py`：组合各周期结果并评分。
- `storage/signal_store.py`：SQLite 事件去重与候选池持久化。
- `notification/notifier.py`：复用企业微信/邮件并增加通用 Webhook 信号消息。
- `monitor/service.py`：单次分析、市场扫描、交易时段判断与常驻循环。
- `main.py`：CLI 入口。

## 缠论工程规则

1. 已收盘 K 线：分钟 K 线按其区间结束时间判断，日线按交易日收盘判断；当前未收盘 K 线先剔除。
2. 包含关系：方向由最近两根互不包含的处理后 K 线确定；两者高低点同时上移为向上、同时下移为向下，否则沿用上一明确方向。发生包含时，向上合并取 `max(high)` 与 `max(low)`，向下取 `min(high)` 与 `min(low)`；时间取较新 K 线，open 取首根、close 取末根、volume/amount 相加。新加入的非包含 K 线与前一处理后 K 线高低点同时上移或下移时更新方向。
3. 分型：使用严格比较。顶分型满足中间 `high` 大于左右 `high` 且 `low` 大于左右 `low`；底分型相反。连续同类只保留更高的顶或更低的底。
4. 笔：只连接交替分型；两端在处理后序列的索引差至少为 `min_bi_bars`（默认 4），且顶价必须高于底价。同类新极值在反向笔尚未确认前替换当前端点。最后一笔始终视为可变的 provisional stroke；只有下一笔被接受后，前一笔才锁定并可参与中枢和信号，`confirmed_at` 取下一笔终点确认时间。这会增加确认延迟，但避免未来极值改写已推送信号。
5. 中枢：从每三个连续已确认笔滑动寻找共同重叠，`ZD=max(三笔低点)`、`ZG=min(三笔高点)`，仅 `ZD < ZG` 成立。后续笔仍与 `[ZD,ZG]` 相交则归入同一中枢，但核心 `ZD/ZG` 固定为初始三笔交集；第一根完全不相交的笔结束中枢。嵌套时默认使用最近结束或正在扩展的同级中枢。
6. MACD 力度：某一完整笔覆盖的已收盘原始 K 线上，对同方向 MACD 柱绝对值求和。两个同向笔之间至少隔一根反向笔才可比较。
7. 一类买/卖：最近同向笔价格创出相对上一同向笔的新低/新高，且 MACD 力度缩小；该笔必须位于最近中枢下方/上方，信号在终点分型确认时成立。
8. 二类买/卖：一类点确认后先有一根完整反向笔，再有一根同向回试笔；二买回试低点不低于一买低点，二卖回试高点不高于一卖高点，信号在回试笔终点确认。
9. 三类买/卖：存在一根完整笔离开中枢，随后完整回抽笔未重新进入核心中枢；三买要求回抽低点严格高于 `ZG`，三卖要求回抽高点严格低于 `ZD`。信号在回抽笔终点确认。
10. 同一确认 K 线出现多个信号时，优先级为三类、二类、一类，但完整结果保留所有命中类型。

信号记录 `structure_time`（极值时间）与 `confirmed_at`（确认时间），去重和新鲜度使用 `confirmed_at`。监控采用逐根回放语义；全历史重算不得修改已经确认并持久化的事件。算法是可复现的工程解释，不声称是缠论流派的唯一画法。

## 0 轴金叉与胜率增强

基础条件为金叉发生且 DIF/DEA 距 0 轴不超过 `zero_axis_tolerance`（以收盘价归一化）。评分附加项包括：

- 大周期 DIF/DEA 位于 0 轴上方或同步向上。
- 当前价格位于 MA60 上方且 MA60 上行。
- 同周期出现缠论买点。
- 成交量不低于近期均量。

买入评分：当前周期 0 轴金叉 30 分；同周期缠论一/二/三买分别 20/25/30 分（只取最高）；相邻大周期 DIF 向上 15 分、位于 0 轴上方再加 10 分；价格在 MA60 上方且 MA60 上行 10 分；量比不低于 1 加 5 分；冲突卖点扣 30 分。

卖出评分：当前周期 0 轴死叉 30 分；同周期缠论一/二/三卖分别 20/25/30 分（只取最高）；相邻大周期 DIF 向下 15 分、位于 0 轴下方再加 10 分；价格在 MA60 下方且 MA60 下行 10 分；放量下跌加 5 分；冲突买点扣 30 分。

买卖最低推送分均为 60。周期缺失不补分。周期权重仅用于同侧信号最终排序：1m/5m/15m/30m/60m/120m/1d 为 1/2/3/4/5/6/8。

这些条件只用于排序和减少弱信号，不等同于收益保证；是否提高真实胜率必须通过目标市场、手续费和滑点条件下的回测验证。

## 调度和降级

- 分钟任务默认每 60 秒检查一次，但只在交易日 09:30-11:30、13:00-15:00 执行。交易日历每日缓存；获取失败时仅以工作日降级并明确告警。
- 首次全市场扫描先执行可续跑的历史回填，日线数据按股票持久化；默认单轮最多 500 只历史请求。成功集合单独持久化，但每轮会重新校验对应本地历史仍存在、至少 120 根且更新至最近应有交易日；上市不足 120 个交易日的股票从覆盖率分母暂时排除并按交易日复查。只有全部符合条件的活跃股票成功后才完成；失败与停牌旧数据不计覆盖率并持续重试。回填完成后，每天用全市场批量快照追加当日 OHLCVA，零价或非法 OHLC 快照被拒绝，再仅对异常/缺口股票补拉历史。
- 高频监控按股票一次拉取 1 分钟增量数据，再本地重采样 5/15/30/60/120 分钟；若 1 分钟历史长度不足，再按需获取较大周期，避免七周期七次请求。
- 日线任务状态持久化；程序错过计划时间后在当日首次启动时补跑一次。
- 数据不足时返回 `insufficient_data`，不伪造信号。
- 东方财富接口失败时可显式切换 AkShare；日线也可切换 Tushare。分钟线无可用提供方时清晰报错，不用日线冒充。
- 120 分钟按交易会话内顺序聚合：上午两根 60 分钟合成一根、下午两根合成一根；不跨午休，不足两根的尾桶不参与策略。
- 默认 `none` 口径下，腾讯日线/分钟线与收盘快照保持一致。若配置复权，所有周期都必须校验提供方能力；腾讯分钟线不支持可靠复权时直接拒绝，不把原始分钟线标为复权。复权模式也不把未复权批量快照追加到历史。120 分钟只从同口径 60 分钟生成。
- 候选池默认 TTL 5 个交易日、容量 100；每日扫描更新分数，过期或低分候选移除，自选股不受 TTL 影响。
- 通知使用 SQLite outbox：分析事务写入事件和每通道待投递记录，worker 用唯一 claim token 租约逐条领取并立即发送，避免批量后半段在等待发送时租约过期；完成/失败更新必须匹配 token，避免过期 worker 覆盖新 worker 状态。失败指数退避，默认最多 5 次。语义是至少一次，`event_id`/`Idempotency-Key` 供接收方去重。

## 安全与风险

- 密钥优先读取环境变量，不在日志打印完整 URL/密码。
- 通用 Webhook schema 为 `quant.signal.v1`，正文包含 `event_id/schema/symbol/name/timeframe/signal_type/side/price/structure_time/confirmed_at/score/evidence/risk_notice`。支持静态认证头；总超时默认 10 秒，不跟随跨主机重定向，校验 TLS，非 2xx 视为失败。企业微信即使返回 HTTP 200，也必须验证 JSON 中 `errcode == 0`。
- 不包含交易账户、自动委托与资金管理操作。
