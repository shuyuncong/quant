二、历史问题复盘（均为收敛前口径，不代表当前代码）

 1. 页面与 engine 的核心权重
    收敛前：页面静态快照与 engine.py 都是核心 65%；文档 §8.5.3 是 40%。
    现在：统一 40/35 + 回填35。65% 只保留在历史回测和工作流页的“停用”对照表中。

 2. 页面数字来源
    收敛前：页面显示 +123.63% / 12.51% / 1.33 / −11.93% / 0.77 / 555 笔。
    回放可复现为 65/35 + 回填35、无 crash overlay：+123.62%。
    现在：页面快照为 +90.01% / 9.84% / 1.20 / −10.19% / 0.63 / 537 笔。

 3. 股灾归因
    收敛前：engine.py 有 “crash 绕过闸门” 的未文档化分支，仓位仍是 65/35、
    波动上限照常，与文档的 30/70、取消波动上限不是同一套。
    +119.96% 是研究版 crash_overlay=True 的反事实，不能标为 engine 的实际口径。
    现在：该分支已删除；crash overlay 关闭，股灾只作为观测字段保留。

 4. 笔数与权益差
    收敛前 65/35 回放：553 笔，最终权益 559057.35740；
    页面快照：555 笔，559077.57046。
    差 2 笔、20.21306 元；先前写成“差 1 笔”是错的。
    差异来源不是评估终止日，而是行情/代码快照不同：
    扩展研究 summary.json 记录的 52 个行情文件与仓库缓存有 47 个哈希不同。

 5. 计划频率
    收敛前：_cycle 无星期判断，每日 fill→plan，等于每日调仓。
    现在：cycle 仍可每日运行（同步、成交已有计划、盯市），但只有周度最后交易日
    生成新计划；非周度末返回“今日只成交与盯市，不生成新计划”。
    周度末判定优先用交易所日历（看下一交易日是否属于下一周），
    取不到日历时退化为“仅周五”，避免用行情末端把周二误判成周末。

 6. 买入估值
    收敛前：卖出用 equity_before，买入却用 equity_after_sells，与回测不一致。
    现在：买卖都用 equity_before * weight，由 test_buy_target_uses_pretrade_equity 锁定。

 7. 页面曲线与运行信号
    收敛前：页面读取静态 metrics/curve，refresh_snapshot 只更新 signal/target，
    曲线对应的是另一套规则。
    现在：backtest.py 直接调用 compute_signal，页面曲线与实时信号同源；
    合成面板上有逐点 parity 测试。
