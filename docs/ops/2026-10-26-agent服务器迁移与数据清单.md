状态：**方案，未执行**。生产 `quant-web` / `quant-backtest`、`config.yaml`、部署脚本与既有缓存均不改。
本文回答三个问题：

1. 迁什么、不迁什么、各自多大；

## 0. 结论先行

- **agent 装在服务器，tmux 里跑**；VS Code Remote-SSH 作为可选编辑器/终端，**不是替代品**
  （Remote-SSH 的终端本来就在服务器上，CLI agent 仍要装）。
- **数据只迁“新增研究数据”**：BaoStock 独立缓存 + 进度 + 名单/清单 + 本轮报告；
  服务器已有的 `backtest-cache`（qfq）与 `output/backtests` 是权威副本，**不要从开发机覆盖**。
- **取数位置先实测再定**：海外服务器到国内行情源未验证；若 5 只测速 >2 倍本机（8–15 s/只），
  取数留在国内，用 `cache_delta` 增量同步（约 80KB/日）。
- 迁移是加法：独立 Linux 用户 + 独立 clone + 独立 venv；**不碰**生产 checkout、docker 组、生产 `.env`。

## 5. 数据迁移

### 5.1 迁移前：停掉本机写入

全池回填与样本构建都是单写者。迁移前在本机终止回填任务（进度以
`_backfill_baostock_20161201_20241231_history_progress.json` 为准），
否则两端会同时写同一进度文件。进度 JSON 在缓存目录内，会随目录一起搬走。

### 5.2 Windows

**Git Bash / WSL（字节流安全）**：本机已验证压缩流大小，613 文件时约 **35.9 MB**（raw 59 MB），
全量预计 ~300 MB。

```bash
tar -C /d/development/github/quant/quant-python/signal_system -czf - cache/baostock_history_20261026 | ssh <server> "mkdir -p /home/agent/quant/quant-python/signal_system && tar -C /home/agent/quant/quant-python/signal_system -xzf -"
```
```bash
tar -C /d/development/github/quant/quant-python/signal_system -czf - output/backtests/_history_expansion_20261026 | ssh <server> "mkdir -p /home/agent/quant/quant-python/signal_system/output/backtests && tar -C /home/agent/quant/quant-python/signal_system/output/backtests -xzf -"
```

**PowerShell（任一版本，最稳）**：`scp` 不做二进制管道转换，目录直接递归复制：

```powershell
scp -r D:\development\github\quant\quant-python\signal_system\cache\baostock_history_20261026 <server>:/home/agent/quant/quant-python/signal_system/cache/
```
```powershell
scp -r D:\development\github\quant\quant-python\signal_system\output\backtests\_history_expansion_20261026 <server>:/home/agent/quant/quant-python/signal_system/output/backtests/
```

> PowerShell 5.1 的原生命令管道可能把二进制当文本处理，**不要**用它做 `tar | ssh`；
> PowerShell 7+ 才行。旧样本（278 MB）只在需要时追加，路径同上。

## 7. agent 形态：装 CLI 还是用 Remote-SSH

**两者不是二选一。** Remote-SSH 只是把 VS Code 的前端接到服务器，终端与扩展宿主都在服务器；
要用 omp / codex，仍然得在服务器上装它们。

| 方式 | 实际运行位置 | 断线/合盖 | 适合 | 代价/风险 |
|---|---|---|---|---|
| **omp / codex CLI + tmux** | 服务器 | 继续跑；会话可 `--resume/--restore` | 长时间回填、批量回测、git 操作、批处理 | 纯终端；需 SSH 与 tmux 习惯 |
| **VS Code Remote-SSH** | 服务器（扩展宿主/终端） | 断开后任务随终端结束 | 编辑、调试、看 diff、远程终端 | 额外内存（数百 MB）；GUI 依赖；不是 agent 本体 |
| 本地 agent + `ssh://` 工具 | 本机 + 远程执行 | 本机休眠即断 | 临时改远端文件 | 长任务不靠谱；数据仍跨网 |

推荐：

1. 服务器装 **omp**（主力）：`omp -p "..."` 做无头批处理，交互式用 tmux。
   安装方式按官方发行渠道（Linux 包/二进制或 Node/Bun 全局），装完必须 `omp --version` 与
   `omp -p "reply OK"` 均通过；登录在服务器完成，**不要把本地 `~/.omp` 整目录拷过去**（只按需拷会话）。
2. 需要时再装 **codex**，与 omp 一样放在 `agent` 用户下；两者**不要同时写同一个 clone**，
   用独立 worktree 或串行执行。
3. 编辑器用 **VS Code Remote-SSH**，只连 `/home/agent/quant`；它不承担长任务。
4. 不给 agent 开公网端口；不装 `ttyd`/`code-server` 到公网。远程一律 SSH。

安全边界：

- `agent` 用户：无 sudo、无 docker 组；生产 `.env` 保持 `600` 且不与其同组。
- provider key 只放 agent 自己的环境/`~/.omp`，不进仓库；`umask 077`。
- 生产部署不变：agent 只推 feature 分支，由 GitHub Actions 部署。
- 资源限制：样本构建 `--workers 2`；pytest 不开 xdist；避免与 `quant-backtest` 抢 CPU。
