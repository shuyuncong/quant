# 市场闸门可观测性（2026-10-14）

## 一、背景

`docs/TODO.md` 与 [2026-10-13 市场闸门核验](2026-10-13-市场闸门核验.md) 第三条建议：
"给闸门加可观测性 —— 现在没有任何『闸门关闭导致错过多少信号』的统计进入日报，
所以『闸门是否过严』只能每次临时写脚本回答（本次就是）。"

本任务只加观测，**不动闸门语义、不动任何生产配置取值**。

## 二、日报的生成路径（改前现状）

`signal_system` 里能被称为"日报"的产物有三处，全部由日线零轴扫描驱动：

| 载体 | 生成点 | 改前内容 |
| --- | --- | --- |
| 扫描产物 `output/scan_*.json` | `monitor/service.py:_save_report("scan", …)`，`scan_zero_axis` 末尾 | `market_context`（含 `allows_entries`/`regime`/五个原始布尔）、候选池、股票池/基本面漏斗、错误 |
| 推送汇总（一条） | `monitor/service.py:notify_scan_summary`（正文 + `evidence`） | 候选数与候选清单；闸门关闭的候选标 `[观察，闸门未开]` |
| Web 结果页"市场环境"块 | `web/src/app/results/page.tsx` 读 `market_context` | 指数 / 环境 / 允许开仓 / 均线多头 |

缺口：三处都只给**当天**的闸门结果，没有任何**历史分布**；`allow_entries=false`
也没说清是哪个条件拦的（`blocked` 被折叠成一个布尔就丢了）。

另注：`notification/notifier.py` 的 `send_daily_report` / `format_signal_report`
是**遗留渠道**，全仓库无调用方（引擎自己的 `notify_scan_summary` 才是生效路径），
本任务没有往里加东西，避免给死代码续命。

## 三、改了什么

### 0. 为什么不改 `strategy/market_gate.py`

`strategy/market_gate.py` 的**字节**被两个预注册完整性审计锁定：

- `canonical_replay_semantics_audit.py:90` `PREREGISTERED_MARKET_GATE_SHA256`
- `entry_context_batch_audit.py:107`（同一哈希）

对拍确认该哈希等于 `HEAD:strategy/market_gate.py` 经换行归一化（LF）后的 SHA256
`fa69dbee01817e44…`，且 `_dependency_contract()` 不匹配即 `RuntimeError`。
因此闸门**判定**所需的代码一个字节都不能动 —— 本任务把可观测性辅助函数放进新模块
`strategy/gate_observability.py`（纯记账，不参与任何判定），
`market_gate.py` / `utils/helpers.py` 保持字节不变。

> 附带发现（非本任务引入）：`utils/helpers.py` 在 HEAD 上就已与
> `PREREGISTERED_UTILS_HELPERS_SHA256` 不符（HEAD 实际 `4a224fad…` vs 预注册
> `3ec75b77…`），即那两个审计当前跑不过。这是既有状态，本任务既没修也没碰它。

### 1. `blocked_by` 拆分，取值与判定同源

`monitor/service.py:_market_entry_context` 新增 `blocked_by`，命名与顺序与
`backtest_winrate.build_market_gate` **逐字一致**（`strategy/gate_observability.py:
MARKET_GATE_BLOCKER_ORDER`）：`below_ma_long` / `ma_long_down` / `macd_death_cross` /
`trend_down` / `ma10_latch_bear` / `macd_latch_bear`。

关键点：`blocked` 现在等于 `bool(blocked_by)`，两者由同一组布尔量推出，
所以"判定"与"观测"不可能漂移；拆分错了就是判定错了，测试能抓住。

### 2. 两块聚合数据

- **指数层逐日分布**：`_record_market_gate_history` 按交易日把
  `{date, allows_entries, blocked, blocked_by, regime}` 覆盖写入
  `run_state["market_gate_history"]`（保留 1200 条），
  `strategy/gate_observability.py:summarize_market_gate_history` 汇总成
  `hits[name].display = "命中天数/总交易日"`。
- **个股层被拦信号数**：`scan_zero_axis` 逐票计数
  `signals_screened` / `blocked_by_market_gate` / `blocked_by_position_gate` /
  `policy_observe_only`，逐批累加进 `run_state["market_gate_signal_counts"]`，
  完成轮读出即清零（避免次日重复计入）。

### 3. 空场次也能读

推送正文无论有无信号都带一行"闸门：开/关（日期，环境，拦下条件…）"；
`market_gate.today.active_blockers` 在闸门开着时是空列表而不是缺失。

## 四、口径边界（避免误读）

1. **只有日线零轴金叉接闸门**。年线趋势与底背离不接，`entry_gate_blocked` 也不写
   它们，因此"被拦下的信号数"仅指零轴金叉。
2. **计数单位不同**：`market_gate.hits` 的单位是**交易日**（指数级，一天一判）；
   `market_gate_signals.blocked_by_market_gate` 的单位是**信号（个股）**。
3. **`gate_unavailable` 不是闸门条件**。`market_gate_fail_open: false` 下数据不足
   按关闭处理，记为 `gate_unavailable`，落在 `other_blockers`，**不污染**六项分布。
4. **全市场模式按批**。`scan_zero_axis` 一天跑多批，`market_gate_signals` 是跨批次
   累加的当日合计；单批明细在 `this_run`。

### 5.2 端到端真实运行（离线回放，不联网）

`_gate_obs_probe.py report` 用本地 `cache/index_000001_sh.pkl` +
`cache/daily_history/*.pkl`（30 只覆盖到 2026-09-01 的票），先逐日走真实的
`_market_entry_context` + `_record_market_gate_history` 写入 1844 个交易日的观测，
再跑真实的 `scan_zero_axis`。`_offline_market` 把 `get_bars` /
`get_stock_pool_history` / `refresh_daily_histories_from_snapshot` /
`latest_expected_trade_date` 全部换成只读本地缓存，回放期间若出现
`gate_unavailable` 会直接抛错（不允许用"数据不足"糊过去）。

扫描产物里新增的两个键（`output/scan_*.json`）：

同一份数据渲染成推送正文：

```
闸门：关（2026-09-01，环境 range，拦下条件 below_ma_long、trend_down）
闸门近 240 日：放行 74/240（2025-09-04~2026-09-01）

因闸门被拦下的信号：1 只（当日零轴信号 1 只，仅日线零轴金叉口径）
```

**这份数据直接可读的结论**（21 个月窗口，1844 天样本）：

- 闸门只在 74/240 ≈ **31% 的交易日放行**，即"大部分时间不许开新仓"。
- 拦下最多的不是长期趋势本身（`ma_long_down` **0/240**、`below_ma_long` 32/240），
  而是**中短期条件**：`ma10_latch_bear` 111/240、`trend_down` 95/240。
  也就是说"闸门过严"若成立，主因是最短周期的 MA10 latch 与 MA20/MA60 趋势，
  而不是 MA250 斜率 —— 这与 TODO 里"`ma_long_up` 把 2024H1 锁死"的直觉不同，
  值得单独验证（本任务不做策略决策）。
- `macd_latch_bear` 恒为 0 是配置使然（`fast_gate_mode: ma10_latch` 不算 MACD latch），
  不是数据缺失。

窗口长度对比（同一份逐日序列，仅改 `window_days`）：

```
120 日：2026-03-11~2026-09-01   放行 15/120   below_ma_long 32/120  trend_down 77/120  ma10_latch_bear 65/120
240 日：2025-09-04~2026-09-01   放行 74/240   below_ma_long 32/240  trend_down 95/240  ma10_latch_bear 111/240
```

240 日 ≈ 一个自然年，能同时覆盖"放行段"与"关闭段"，所以日报默认取 240 日；
120 日只剩最近的关闭段（放行率从 31% 掉到 12.5%），单看图会误判"闸门更严了"。
这正是"不要引用单窗口结论"的同一个坑。

  --start 2018-07-01 --end 2026-09-01

# 2. 端到端日报块（离线，不联网；日期会与指数缓存末日对齐）
