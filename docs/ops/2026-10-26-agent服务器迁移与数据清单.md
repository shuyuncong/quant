## 7. agent 形态：装 CLI 还是用 Remote-SSH

**两者不是二选一。** Remote-SSH 只是把 VS Code 的前端接到服务器，终端与扩展宿主都在服务器；
要用 omp / codex，仍然得在服务器上装它们。

| 方式 | 实际运行位置 | 断线/合盖 | 适合 | 代价/风险 |
|---|---|---|---|---|
| **omp / codex CLI + tmux** | 服务器 | 继续跑；会话可 `--resume/--restore` | 长时间回填、批量回测、git 操作、批处理 | 纯终端；需 SSH 与 tmux 习惯 |
| **VS Code Remote-SSH** | 服务器（扩展宿主/终端） | 断开后任务随终端结束 | 编辑、调试、看 diff、远程终端 | 额外内存（数百 MB）；GUI 依赖；不是 agent 本体 |
| 本地 agent + `ssh://` 工具 | 本机 + 远程执行 | 本机休眠即断 | 临时改远端文件 | 长任务不靠谱；数据仍跨网 |

推荐：

1. 服务器装 **omp**（主力）：`omp -p "..."` 做无头批处理，交互式用 tmux。
   安装方式按官方发行渠道（Linux 包/二进制或 Node/Bun 全局），装完必须 `omp --version` 与
   `omp -p "reply OK"` 均通过；登录在服务器完成，**不要把本地 `~/.omp` 整目录拷过去**（只按需拷会话）。
2. 需要时再装 **codex**，与 omp 一样放在 `agent` 用户下；两者**不要同时写同一个 clone**，
   用独立 worktree 或串行执行。
3. 编辑器用 **VS Code Remote-SSH**，只连 `/home/agent/quant`；它不承担长任务。
4. 不给 agent 开公网端口；不装 `ttyd`/`code-server` 到公网。远程一律 SSH。

安全边界：

- `agent` 用户：无 sudo、无 docker 组；生产 `.env` 保持 `600` 且不与其同组。
- provider key 只放 agent 自己的环境/`~/.omp`，不进仓库；`umask 077`。
- 生产部署不变：agent 只推 feature 分支，由 GitHub Actions 部署。
- 资源限制：样本构建 `--workers 2`；pytest 不开 xdist；避免与 `quant-backtest` 抢 CPU。

## 11. 双机分工：Oracle 工作机 + 家庭服务器取数备胎

### 11.1 角色与单写者规则

| 角色 | 机器 | 职责 | 明确禁止 |
|---|---|---|---|
| 取数发布方 | 家庭服务器（默认） | 跑 `backfill_history_cache.py`，写自己的研究缓存；用脚本推送到 Oracle | 不在 Oracle 同时跑同一缓存 |
| 工作机/接收方 | Oracle | agent、样本构建、回放、pytest；**只读消费**缓存 | 不写同一缓存目录、不改发布方进度 |
| 备用发布方 | Windows / Mac | 家庭服务器离线或网络异常时接管 | 不双开、不跳过进度文件复制 |

**同一时刻只能有一个发布方。** 切换发布权必须先把缓存目录（含进度 JSON）复制给新发布方，
再停掉旧发布方；否则两端各自追加，除权与进度都会分叉。

同步脚本：`docs/ops/sync-research-cache.sh`（家庭服务器 → Oracle，带 `flock` 互斥与 `DRY_RUN`）。

### 11.2 为什么用 rsync，而不用 `cache_delta`

`cache_delta.py` 的增量 schema 只含 8 个标准列：

```text
STANDARD_COLUMNS = [datetime, open, high, low, close, volume, amount, is_closed]
```

它**不携带 `turnover_rate`**（`cache_delta.py:52` 的 `STANDARD_COLUMNS`）。研究缓存少了换手率，
`liquidity_strategy_study` 会整批判为不可评估。

本地往返实测（3 行基线 + 追加 1 行）：接收方得到 4 行，但**新增行的
`turnover_rate = NaN`**，其余列与 attrs 正常。因此：

- 研究缓存：`rsync` 整文件同步（研究批次不是每日增量，一次全量 300–500 MB 可接受）。
- 生产日线缓存（无额外列）：仍可用 `cache_delta` 的 delta/full 机制，二者不冲突。

### 11.5 故障切换

| 情形 | 动作 |
|---|---|
| Oracle 直接取数也够快 | 家庭服务器保持备用：不跑回填，只保留 venv/clone；Oracle 为发布方，完成后可反向同步给家庭服务器 |
| Oracle 取数慢/超时 | 停 Oracle 回填；把 Oracle 缓存+进度 rsync 到家庭服务器；家庭服务器接续并推送回 Oracle |
| 家庭服务器离线/断电 | 由 Windows/Mac 接管发布权（同一缓存+进度），完成后直接 `scp`/`tar` 到 Oracle |
| 网络全断 | 停止取数；Oracle 继续用已有数据做回放；不改进度文件 |
